# Towers routine notification source overlay

The stock research-completion text is generated by `research.cpp`, separately
from the existing `BNTECHDONE` scenario event. The successful native F7 save
message is generated by `keybind.cpp`. Both are rendered inside the game canvas,
so CSS and the custom HTML notice cannot remove their purple console duplicates.

These two full source files change only those routine success messages. The
file-local helper opens `/tmp/warzone-towers-ui-v34` and opts in only when its
first byte is `1`, under Emscripten. The Towers host creates this transient
marker before native startup; the Duel document does not. It is outside the
persistent configuration/save directory and is absent from desktop builds.
Without the marker, both stock notices retain their original behavior.

Research sound, upgrades, completion state, scenario events, queues and all
other native console messages remain untouched. The successful save call is
still executed in its original branch; save failures and prohibited-save
messages are still displayed. No global console clearing/filter is introduced.
The HTML notification must use the actual `BNTECHDONE` payload and actual save
acknowledgement, rather than a tap or estimated research duration.

`source-overlay.json` records exact original/overlay hashes against the complete
unchanged `archive/native-blueprint-4.7.0-source.tar.gz`. The earlier v0.31
`display3d.cpp` overlay stays in force. To rebuild from a fresh Linux/WSL workspace
with the original native build prerequisites:

```sh
python3 tools/build-native-notices-034.py --workspace /absolute/empty/workspace
```

`--verify-only` checks the pinned recipe, overlays and shell syntax without a
build. `tools/prepare-native-notices-034.py` checks the ready source cache and
matching baseline artifacts before preparing these overlays. The shipping build
uses a bounded incremental compile of these two files and one native link,
integrated through the existing matched-runtime tool while retaining all authored
virtual files. The build and runtime-integration records are separate from the
exact-APK emulator observations; source/build checks do not establish gameplay.

The recorded incremental command, against the prepared v0.31 cache before this
build, was:

```sh
python3 tools/build-native-notices-034.py \
  --incremental-cache /home/punkech/wz-blueprint-20261107 \
  --raw-out /mnt/c/timerApp/_release-records/native-notices034/raw
```

Only `research.cpp.o` and `keybind.cpp.o` compiled. The existing target also ran
its normal stock data-generation tasks; none of that generated data was shipped.
`tools/integrate-native-runtime.py` retained the exact authored package/index,
private worker-output hook and early FS exports when installing the newly
generated matched JS/WASM pair. The generated loader's ASM_CONSTS addresses shift
with native layout, so it must accompany the new WASM. Its generated code remains
exact outside the two reviewed integration replacements. Scenario source updates
are appended independently after this native integration and audited separately.
