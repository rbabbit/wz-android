# Warzone Towers 0.14

Towers adopts the approved compact, border-free Production, Design and Research
references across its active pages. Build, the phone blueprint library, activity
queues, Help, the header and field controls use the same tighter spacing and
flat rows. Real game artwork, native facility IDs, costs and manual orders stay
in use. The unsupported stock Commander shortcut is removed from Towers;
Commander game capability and the deferred Duel interface remain available.

The activity footer and current-work sidebars retain their 0.13 source and
original hide, restore and collapse behaviour. Native game selection/placement
outlines and visible keyboard-focus cues remain meaningful input feedback.

The Towers Android start, Graphics, Music and Return-confirmation views receive
matching compact styling. Their mode guards retain Duel's existing default
appearance. Back/input routing, preferences, downloads, icon, app name and game
logic retain their existing behaviour.
Music also adapts to short screens so complete track rows and its actions stay
visible.

In-game pages are HTML/CSS over the existing WebAssembly engine; launch/settings
views and the Return confirmation are Android views. All nine Towers/Duel
program, WASM, data and entry files, maps and scenarios remain byte-identical
to 0.13. Private phone designs still need compatible factories and the current
game's research before production. No factory ETA or percentage is invented.

The accepted 0.13 APK and complete source are retained in
`C:/timerApp/fallbacks/towers-before-compact-0.14-20261108/`. Before edits, all
7,498 manifest files and every one of the source ZIP's 7,499 entries were checked
against the working tree with CRC/SHA and byte comparisons. Older fallbacks,
the immutable GitHub benchmark and separate v6.4 remain preserved.

The [page inventory](../../qa/test-14/page-inventory.json) distinguishes actual
normal/compact screen cases, protected pages and source-only exceptional states.
Native loading, engine-error and battle-exit/replay/outcome surfaces are retained
source-only paths; they do not establish a newly completed campaign or victory.
The [exact-APK report](../../qa/test-14/REPORT.md) records delivery evidence and
limits; planned entries and source tests alone do not certify gameplay.
Maximum-facility tests reuse a disclosed complete native save with five labs,
five vehicle factories and five cyborg factories. Ordinary production, manual
research, phone saves/keyboard and building/movement checks remain separately
identified. Software-emulator black terrain, physical-handset GPU/FPS, audio
and a complete 30-wave victory remain outside newly certified scope.

The evidence retains ordinary FIFO/production and initial phone-save records
under their original APK identities. Specific APK/source comparisons cover the
Build-queue reservation, Towers scroll-owner fixes and native Music-only change;
all 473 HTML/game assets are identical between R4 and the R5 delivery candidate.
Current page captures, remaining Library/Design actions, keyboard returns,
native Music and gameplay checks are identified separately. Rejected earlier
captures remain diagnostics. Linked stages do not claim one uninterrupted run.

The recorded current HTML-control checks use standard trusted CDP
Input.dispatchTouchEvent touchStart/touchEnd with explicit 60 ms timestamps in
the actual emulator WebView, without an experimental compositor API. World selection, movement,
building, native Android controls and system Back retain OS/ADB input. These
are actual UI touch events, rather than programmatic DOM button clicks;
physical-handset input latency remains outside this emulator verification.

The package ID and signing identity remain unchanged, so 0.14 updates 0.13 and
retains private phone designs and saves. Version code/name are `14` / `0.14`.
