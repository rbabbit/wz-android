# Warzone Towers 0.20 — landscape remakes and swipe cue

Version 0.20 remakes the 43 generated Towers maps as individual native
landscapes, using the existing Dustfall and Iron Valley maps as visual
references. The change addresses the repeated corridor/base appearance of
0.19. Map names and IDs remain the same. The home map cards gain a visible
chevron with a 48dp tap target: it advances to the next map, while the last
card points back. Swiping remains available.

The catalog remains **46 maps: 16 Easy, 15 Medium and 15 Hard**. The remade
set is still 15 Easy, 15 Medium and 13 Hard; Greenhaven belongs to Easy and
the original Dustfall and Iron Valley belong to Hard. Wave schedules and
starting preparation times remain unchanged: generated Easy maps have
15 rounds/240 seconds, Medium 20/180 and Hard 25/150. Greenhaven retains
15 rounds and the original two maps retain 30.

The change is restricted to the generated maps' native terrain, elevations,
scenery, starting layouts, actual-data previews and art metadata, plus the
native home-card chevron. The three original map sources, all wave profiles,
game rules, command/research/production code, Duel payloads and saves remain
outside this change. Every remade map must retain a human-owned Satellite
Uplink Centre inside its rear base, spaced away from other structures and
the enemy approaches.

The old generated maps are preserved in
`C:/timerApp/old_maps-0.19.zip`: **528 preserved files plus a manifest, 879410 bytes**. Its SHA256 is
`b48e089c99ec5e60f2aa5ccc9896dfd38fc7dc0b030c276e4c38e95aa429ac3d`.
The complete 0.19 APK, source ZIP and checksum file remain unchanged.
Their exact paths, sizes and hashes, together with the old-maps backup, are
recorded in [archive/fallback-0.20.json](../../archive/fallback-0.20.json).
GitHub `main` and `v0.17-benchmark`, older releases and v6.4 remain preserved.

`tools/generate-levels-020.py` authors the new native map sources and
previews. `tools/build-levels-020.py` appends those bytes to the exact 0.19
data package and reindexes only the 43 map payloads and their registration
stanzas. Its integrity proof is
[archive/levels-0.20-package.json](../../archive/levels-0.20-package.json).
The complete existing data prefix, compiled engine program body and WASM
remain frozen. No new wave scheduler, terrain renderer or game engine is
introduced.

Verification is limited to source/art review, static generation constraints,
an Android build and packaging integrity checks. **No emulator, gameplay,
native pathfinding, difficulty, full-wave or home-arrow operation testing
is authorized for this revision.** Native-data preview renders show the
authored terrain and actual game assets; they are not gameplay screenshots
or proof of in-engine appearance. Previous home-screen QA is historical.
The release record must state the exact build/review evidence available;
the notes alone do not establish that those steps have finished.

The final 43-map native-byte review passed, and the clean Android build
completed successfully. The review checked terrain tables, height bounds,
four water vertices, spawn borders, closed scenic plateaus, starting objects
and uplink clearance. Its source-only report is
[archive/map-art-0.20-source-review.json](../../archive/map-art-0.20-source-review.json).
The actual-data overview is `map/levels/SCENIC-OVERVIEW-0.20.png`.
None of these observations establishes in-engine appearance or gameplay.

The Android package remains `com.rbabbit.warzonetowers.lab`, labelled
**Warzone Towers**. Intended delivery names are `Warzone-Towers-0.20.apk`,
`warzone-towers-0.20-source.zip` and `Warzone-Towers-0.20-SHA256.txt`.
`tools/package-20-build-only.py` checks the frozen 0.19 fallback, the exact
native-map replacement inventory, preserved non-map assets, APK/source
correspondence and complete source ZIP contents before creating them.
