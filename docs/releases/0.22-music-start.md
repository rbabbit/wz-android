# Warzone Towers 0.22 — music startup and retry repair

The 0.21 music player could remain on **Starting music…** without producing
sound. Its Android response pre-applied a media seek range, then WebView's
stream reader applied that range again. Requests for the end of an Ogg track
could consequently seek to the wrong data or fail. The player also lacked a
startup/buffering deadline, and **On** could not replace an already-pending
play request.

Version 0.22 obtains only the complete assigned track through an ordinary
local request, validates its bounds, and gives the audio player a Blob URL.
The media decoder handles seeking inside that Blob. The local endpoint serves
one bounded complete track and rejects ranged requests; it never exposes the
rest of the verified optional pack. It does not download the full 114 MB pack
again or mount that pack into the game's heap.

Startup, buffering and explicit retries are bounded. An unsuccessful start
shows a compact retry message rather than waiting forever. **On** can replace
a stuck attempt. Pending loads, timers, media elements and Blob URLs are
cancelled or released when music is turned off, the app is backgrounded, the
track changes or the battle exits. Sound effects and voices remain independent.

Assignments, original music bytes, optional-download verification, the splash
screen, the header layout and the saved phone preference remain unchanged.
All maps, wave schedules, research, production, saved templates, native game
data, compiled program body/WASM and dormant Duel payloads are preserved.
The complete 0.21 APK, source ZIP and checksums remain available, with hashes
recorded in `archive/fallback-0.22.json`. GitHub `main`, `v0.17-benchmark`, older
artifacts and v6.4 remain untouched.

Verification for this revision comprises focused source-level checks, source
review, Android compilation and package/source integrity checks. Source-only
fixtures can exercise response byte boundaries, hung promises, cancellation
and retry; they do not reproduce real Android media decoding. **No emulator,
device playback, audio-focus or gameplay test is performed.** Earlier QA
reports are historical and do not establish playback of this revision.
Build/review completion must be tied to the final recorded evidence rather
than assumed from these notes.

The final source reports passed checks for all 39 original track hashes and
stream boundaries, plus 16 simulated player cases covering Blob loading,
timeouts, retries, cancellation and late completion. The clean Android build
and final asset assembly passed. The reports are retained in `archive/` and
hash-bound to the delivery proof. These results do not verify device playback.

The focused source checks passed: the actual Java reader reproduced the old
range-bounds failure in a model of Chromium's range rule, and its repaired
reader returned all 39 original track hashes with correct boundaries. The
actual loader passed 16 deterministic Node-VM cases using synthetic media,
fetch and time. These cover pending start/retry, fetch/body/play timeouts,
buffer recovery, cancellation and cleanup. The retained Duel loader suffix
is byte-identical to 0.21. The independent review is in
`archive/music-0.22-source-review.json`; fixture records are
`archive/music-stream-0.22-checks.json` and
`archive/music-0.22-player-checks.json`. These are source-level observations,
not successful Android audio playback.

The Android package remains `com.rbabbit.warzonetowers.lab`, labelled
**Warzone Towers**, with version code 22 / version 0.22. Intended outputs are
`Warzone-Towers-0.22.apk`, `warzone-towers-0.22-source.zip` and
`Warzone-Towers-0.22-SHA256.txt`. The source archive retains the complete native
source, all map sources and the dormant Duel implementation.
