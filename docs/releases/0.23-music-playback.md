# Warzone Towers 0.23 — focused music playback repair

The user reported that the delivered 0.22 APK still did not play its assigned
music. This revision is restricted to reproducing that failure in the real
emulator, correcting the affected music implementation and checking the exact
delivery APK. Earlier source-only fixtures did not establish Android playback.

Reproduction on the delivered 0.22 APK found an actual response header of
`2418624, 2418624` for Greenhaven's 2,418,624-byte track. WebView generated a
Content-Length header and the native response added the same field again.
The loader converted that comma-separated value with `Number`, received NaN
and rejected the track before creating an audio element. A direct fetch showed
the complete expected body and original track hash, so this rejection was a
header-validation bug rather than evidence of missing music bytes.

The focused repair omits the redundant native GET Content-Length field and
accepts a repeated length field only when each value equals the assigned
track's expected length. The complete body-length validation remains in place.
The full-track Blob transport, deadlines, retry and cleanup from 0.22 remain.

The emulator initially had no current optional music pack. The test environment
uses a disclosed copy of the canonical verified pack to reach the affected
playback path quickly. This does not verify downloading, cancellation or resume
for this revision, and no such download-flow success is claimed.

The earlier emulator session logged audio HAL output failures for engine sound
effects as well as music. Following cold recovery, no new HAL error was shown;
speaker output was not monitored, so current host-speaker availability remains
unknown. Decoded audio is not presented as sound heard through the speakers.

On the exact candidate APK with SHA256
`af42705865e83cd80b0fa1f631f5e90753869d35e2ec8f6e334f40d603658f44`,
the original browser audio element advanced from 0.079090 to 1.882702 seconds,
remained unpaused at readyState 4, and had no media error. Its live captured
audio stream produced measured PCM RMS 0.06067919 and peak 0.19861606. Music
On, Off and On again passed in the real emulator. The observer retained the
original media element and did not replace fetch, decoding or playback.
`qa/0.23-music/playback-observed.json` retains the raw observations. These
verify transport, decoding and media progression; audible output is explicitly
unverified. The final hash-bound report records that distinction.

Delivery verification is recorded in the hash-bound emulator report, separately
from source/package integrity checks. Only checks actually present there are
claimed; the observations above do not establish complete lifecycle, gameplay,
map balance or all-track playback verification. Earlier source-only reports
remain historical.

All maps, wave schedules, research, production, templates, game controls,
native program/data/WASM and dormant Duel payloads remain outside the change.
The complete 0.22 APK, source ZIP and checksum file are preserved by hash
reference in `archive/fallback-0.23.json`. Older benchmarks, releases and the
separate v6.4 fallback remain preserved.

The Android package remains `com.rbabbit.warzonetowers.lab`, labelled
**Warzone Towers**, with intended version code 23 / version 0.23. Intended
delivery names are `Warzone-Towers-0.23.apk`, `warzone-towers-0.23-source.zip`
and `Warzone-Towers-0.23-SHA256.txt`. The source archive retains the complete
native source, all map sources and dormant Duel implementation.
