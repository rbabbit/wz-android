# Warzone Towers 0.27 — saved games and in-game Rewards

Save Game stores the current native game files on the phone, and Saved Games
on Home lists the available matches to resume. The save retains its map and
reward-run identity so loading cannot issue a second starter gift, repeat
already credited wave coins or restore purchases already consumed in that run.

The emulator's native `writeGameFile` error identified the reproduced save
failure: `Greenhaven-Beginner-T1` exceeded the native GAM header's 19-byte name
limit (`MAX_LEVEL_SIZE` includes the terminating NUL). Its internal alias is
shortened to `Greenhaven-T1`. The displayed name, terrain, artwork, starting
objects, difficulty and authored waves remain unchanged. Catalog, challenge
and registration metadata use the same corrected alias. F7 input cleanup also
releases left/right modifier keys as a separate input guard.

The phone archive enforces the same UTF-8 name limit on save and load. Focused
JVM fixtures check the 19/20-byte boundary and all 46 catalog native names,
complete binary/nested file roundtrips, native metadata identity, required save
files, damaged manifests/payloads, path safety, size/slot limits and atomic slot
visibility. These use synthetic native bytes and a host-private directory.

Rewards purchases are available during a Towers match with the existing
catalog prices, wallet and item limits. Active purchases use native transaction
acknowledgements rather than granting units or bypassing normal building power
costs. The three-fortress limit remains. The five-coin cleared-wave notice is
kept compact in the game header.

On the exact candidate APK with SHA256
`5014b70184f120f0f237f33aef730981793b4dc982f255658290e4505370ad51`,
the focused emulator check observed a real Greenhaven native save with the
corrected `Greenhaven-T1` identity and completed persistence callback. The phone
archive appeared in Home's Saved Games list and loaded into a fresh WebView
document with its original reward run. Four stationary truck IDs/positions and
the Ripple/Archangel purchase journal and remaining allowance were retained.
The ordinary first wave then cleared on that exact APK and the wallet changed
from 295 to 300, with the small +5 notice inside the header. This wave observation
used no seeded/debug world state.
After returning Home, force-stopping and restarting the app, the earlier
wave-zero save loaded again with balance 300 retained, the original economic
run, both purchase journals and one Ripple/one Archangel allowance. The fresh
document did not repeat the charge or starter gift. Repeated Home/Load returns
restored input without exposing the stock pause menu.
