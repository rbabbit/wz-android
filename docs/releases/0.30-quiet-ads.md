# Warzone Towers 0.30 — quieter optional ads

This test version keeps the normal Towers launch focused on map selection and
playing. The ad action is a compact, subdued row inside Rewards instead of the
bright full-width strip above the shop. The reward remains ten crystals per
earned native SDK event; existing balances, inventory and purchase limits are
unchanged.

Google's consent information is refreshed quietly for the current app session.
The visible required consent form and ad loading are tied to an explicit Watch
action. No rewarded ad is requested or preloaded just because Home appears.
Leaving the Rewards flow cancels an outstanding watch request, so late network
callbacks must not open an ad over another screen. The affected controller
fixtures and the exact-APK observations record which of these paths ran.

The manifest now uses the actual Towers AdMob app ID
`ca-app-pub-3430279660625393~3119801475`, including in the test build. UMP can
therefore retrieve the publisher's own published app name, logo and message
styling when consent is required. Those details are configured in AdMob and
are not recreated or silently replaced inside the Android app.

An update from the 0.29 test APK can retain UMP preferences associated with
Google's old sample app ID. This test build performs a one-time identity
migration through UMP's public reset API, with a persisted completion marker,
before requesting current consent information. The migration runs only in
test-ad builds; production does not reset consent. It does not read or change
the crystal wallet, purchases, game saves or other player data.

The fresh emulator's actual geographic response was `NOT_REQUIRED`, so the
European consent form and its published branding were not visually verified.
The APK manifest's publisher app ID is checked; that check is separate from
observing a region-specific form on a device where Google requires it.

The delivered `Warzone-Towers-0.30-Test-Ads.apk` uses Google's official sample
rewarded unit `ca-app-pub-3940256099942544/5224354917` on physical phones as
well as the emulator. It does not earn advertising revenue. This configuration
uses the existing `assembleDebug -PadmobLiveAds=false` build option; the app
ID and rewarded-unit ID deliberately serve different purposes.

AdMob's format choices for the publisher's live unit, such as disabling ad
pods or interactive creatives, do not control Google's sample unit. Google
and the advertiser still control the rewarded creative, installation/end-card
content, countdown and close controls. This version does not claim to restyle
that fullscreen content or guarantee a particular demo-ad duration.

The app package, real icon and label remain Warzone Towers. Version code 30
and the same signing certificate allow it to update the installed app without
an uninstall. The complete 0.29 APK/source and earlier phone test APK remain
frozen by `archive/fallback-0.30.json`; v0.28, v6.4 and older fallbacks remain.
There are no VPS, GitHub publication or AdMob dashboard changes in this task.

All 527 bundled game assets, including native engine JS/data/WASM, all 46 maps,
music and dormant Duel content, remain byte-for-byte identical to 0.29. The
wallet and save implementation are unchanged. New host controller fixtures
simulate SDK callbacks and are separate from actual Android/network evidence.
Only the hash-bound observations in `qa/0.30-ads/focused-emulator-proof.json`
establish behavior of the exact delivery APK. No full campaign, all-map pass,
physical-phone test, live-ad fill or advertising revenue is implied.

Delivery files are `Warzone-Towers-0.30-Test-Ads.apk`,
`warzone-towers-0.30-source.zip` and
`Warzone-Towers-0.30-Test-Ads-SHA256.txt`.
