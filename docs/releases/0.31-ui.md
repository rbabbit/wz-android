# Warzone Towers 0.31 — clearer controls and header navigation

This version implements the agreed interface changes from the four phone
screenshots and the follow-up menu instructions. The top **RESEARCH** button
replaces TECH with a white background and black text/icon. It still opens the
full research page; the footer Research/Production controls keep their separate
current-activity sidebars.

Build, Production, Queue, Research, Music, Rewards and Help open from the header
and close when the same header button is tapped again. Menu switching uses the
existing close APIs, including safe build exit and research queue synchronization.
The header remains reachable while Help or native Rewards is open. The redundant
Build/Rewards X controls, Production/Queue/Research Back to Battle controls, and
both Help Close/Back to Battle controls are removed. Android Back still closes
the current panel before offering Return to Main Menu from the battlefield.

Production retains its real factory choice and native FIFO order handling.
Produce has a clearer label and immediate pressed/pending feedback; success is
shown only after the native engine accepts the order. The current/queued unit
display continues to use engine state. No synthetic queue entry or optimistic
reward is used as proof that work was accepted.

Rewards now exposes a compact filled **Gain 10 Crystals** button with an explicit
Watch an ad description. Loading, cancellation and the native earned callback
retain their existing semantics. The wallet, prices, purchase limits, earned
amount and consent controller are unchanged. This delivery continues to use
Google's official sample rewarded unit on phones and the emulator, with the
publisher app ID for UMP configuration. Google controls the video, end card and
close controls; this UI change does not restyle the Google creative or enable
live monetized advertising.

The blue map name and elapsed time behind the footer came from two native
`draw3DScene()` text render calls. Only those two calls are suppressed in the
complete `display3d.cpp` overlay under `archive/native-hud-0.31`. The prepared,
verified source cache rebuilt that compilation unit and relinked the engine.
The integrated JS loader, virtual data package, package index, private output
hook, all authored maps, scenario rules, music and dormant Duel content stay
byte-identical to v0.30. The WASM changes through this guarded source build;
it is not described as byte-identical and was not patched as a binary.

The complete source ZIP includes the unchanged original full native source
bundle, the exact full-file overlay and two-call patch, source guards, original
pinned build recipe, and `tools/build-native-hud-031.py` fresh-build wrapper.
See `archive/native-hud-0.31/README.md` for the build inputs and usage. A fresh
dependency/toolchain build was not repeated; the build/integration records
disclose the actual incremental compilation separately from runtime testing.

Only the hash-bound observations in
`qa/0.31-ui/focused-emulator-proof.json` establish behavior of the exact delivery
APK. The command/navigation host fixtures execute actual interface functions
against controlled host replies; they are not emulator or native gameplay
evidence. Validation does not imply a full campaign, all-map graphics pass,
physical-phone ad test, live-ad fill, revenue or region-specific consent-form
acceptance. Any emulator rendering or fixture limitations belong in that report.

The same app ID and signing certificate allow an update over the existing app.
Version code/name are 31/0.31. `archive/fallback-0.31.json` preserves the complete
v0.30 APK, source and checksums; all older fallbacks and v6.4 remain. No GitHub,
public privacy site, VPS or AdMob dashboard changes are included.
