# Warzone Towers 0.33 — compact Rewards and Save response

The selected Rewards direction uses the complete reward row as the purchase
target. A completed tap requests one item at its displayed crystal cost. The
separate BUY button, purchase quantity controls, instruction line, large Rewards
heading and footer are removed. The compact Gain 10 Crystals action occupies the
top line. Home and in-game Rewards retain the existing item artwork, categories,
wallet rules, inventory and limits. A row shows its pending state until native
purchase acknowledgement, then updates the wallet and count with brief feedback
inside that row. Scrolling the catalogue does not purchase an item.

The drawer targets 38% of the available width, bounded to 330–420dp so short
phones retain readable item names and practical full-row touch areas. It keeps
scrolling for shorter screens and larger text. Home displays Stored and Selected
counts separately. Tapping Selected opens a small native quantity popup from
zero through the available stock, subject to the existing match limits; changing
that selection does not buy more stock. There is no owned-item footer or stepper.

Save acknowledges the tap immediately with SAVING and disables repeated input
while work is pending. SAVED is shown after the native save and phone archive
are verified; a failure reports its reason and permits a retry. A responsive
appearance alone is not proof that a save completed: delivery evidence must
also show actual phone persistence and loading of the native run. Saved file
encoding, identity, reward reconciliation and native game payloads remain
protected against v0.32.

A small Privacy action appears on the same top line as Gain when Google UMP
requires a privacy-options entry. It opens the existing Google privacy form.
Privacy is not moved into Help, and a new Home gear/settings redesign is not
part of this version. The ad SDK, consent identity and sample rewarded-ad
configuration remain unchanged. Ten crystals are still awarded only by the
existing earned-reward callback. Emulator ad checks use Google test traffic,
normal ad completion and the real callback rather than synthetic rewards;
they do not establish live ad serving or account approval.

The exact screens, affordances and runtime observations accepted for delivery
are recorded in the hash-bound root emulator proof supplied to
`tools/package-33-rewards-save.py`. It requires focused observations of direct
one-item purchases, Save response and real persistence, Home/in-game layouts,
and privacy access on the exact APK. The final report distinguishes completed
observations from anything still pending; this release note is not standalone
runtime evidence. It does not establish a full-game, all-map, combat, live-ad or
physical-phone acceptance pass.

The complete v0.32 APK, source ZIP and checksum file remain unchanged under
`archive/fallback-0.33.json`. Source preservation compares directly against the
immutable v0.32 source ZIP and its complete file manifest, without requiring a
v0.32 Git commit. The original native engine, full base source and v0.31 HUD
overlay, all 46 levels, scenario catalogues, Duel implementation, soundtrack,
music delivery code, save codec/store and reward policy remain frozen. There is
no native engine rebuild or soundtrack re-encoding in this version.

After the focused exact-APK checks pass, packaging verifies the signing identity,
APK CRC/assets, source preservation, fallback hashes and all evidence hashes.
The complete source ZIP includes the original soundtrack and complete native
source once, excludes local caches and emulator data, streams every packaged
entry through CRC/SHA checks, and must remain below the 2 GiB release-file limit.

Outputs are `Warzone-Towers-0.33-Test-Ads.apk`,
`warzone-towers-0.33-source.zip` and
`Warzone-Towers-0.33-Test-Ads-SHA256.txt`. This task does not publish to GitHub,
modify the v0.31 benchmark or older fallbacks, change the privacy website or
write VPS files.
