# Warzone Towers 0.34 — compact game notices

This version addresses the defeat transition, routine game notifications and two
page close controls. It does not redesign Rewards, change the economy or alter
map content. Research and Production use the existing header toggle to return
to play; their top-right X buttons are removed. Other close controls retain
their existing behavior.

Research completion appears in a compact black panel with white text instead
of the stock Warzone console block. Save success says exactly “Game saved” only
after the existing save/archive success path. Failures remain visible and do
not claim that saving succeeded. The upcoming wave's real unit composition is
shown compactly at the top right without replacing the existing wave controls.
Defeat returns to Home at the same selected map without displaying the stock
Warzone result screen during that transition.

Two narrowly guarded native source changes prevent duplicate stock research
completion text and successful QuickSave console text while the Towers host's
transient `/tmp/warzone-towers-ui-v34` marker contains `1`. Audio, completed
research effects, script events, actual save writers and error paths remain
protected. The original full native source bundle and previous v0.31 HUD source
overlay are preserved. The new `archive/native-notices-0.34` directory contains
the two full C++ overlays, exact patch, source hashes and reproduction notes.
`tools/build-native-notices-034.py` provides the guarded build recipe.

The delivery runtime is a matched source-built JavaScript/WASM pair. The ready
native cache was used for bounded incremental compilation of `research.cpp` and
`keybind.cpp`, followed by one link. This is recorded as an incremental build,
not a fresh complete build. The linker can change generated addresses, so the
old compiled loader is not reused with the new WASM. The integration retains
the original authored-data index and existing private worker-output hook, and
otherwise preserves the new generated loader exactly.

After runtime integration, `tools/embed-notices-034.py` appends and reindexes
only `warzone-towers-objective.js` and `warzone-towers-waves.js` from `scenario`.
All original native data bytes remain as an unchanged prefix. The final package
guard resolves every virtual file against the frozen v0.33 APK and permits
only those two script replacements. All 46 maps, original music, catalogues,
dormant Duel code, reward policy, wallet, save codec/store, ad controller and
publisher consent identity remain protected. Rewarded advertising still uses
Google's sample rewarded unit; this version does not enable live advertising.

`tools/check-notices-034.py` records source/native preservation only. It does
not establish screen, input or gameplay behavior. `tools/package-34-notices.py`
requires a separate root-observed emulator proof bound to the exact candidate
APK. Required observations are defeat without a stock result flash, actual
research completion, the exact save success message with real persistence,
the real incoming-wave preview and the two close-control removals with header
toggles/input restored. Actual viewport, density and font scale are recorded,
including a small phone configuration. Seeded fixtures must be described in
the proof. A focused verification does not claim all-map, full-game, physical
phone or live-ad acceptance.

The exact delivery APK was observed with genuine native research completion,
phone save/archive acknowledgement, a genuine archived game resumed and saved
again, repeated header/footer page toggles, and the native upcoming-wave roster.
Compact screens were checked at 1080×600 and 960×540, density 240dpi, including
font scale 1.3. The defeat check loaded a copy of a genuine save with only the
human Command Centre removed; it verifies native HQ-loss handling rather than
a naturally lost match. All 385 recorded transition frames were reviewed and
no stock results screen was seen. The emulator's original 98 private files and
display settings were restored after testing.

One save after changing the live display/font configuration returned a native
persistence error. Reloading a genuine archive recovered the session and three
following genuine saves succeeded. Save writers and storage logic were outside
this change. The existing emulator renders terrain black, so these observations
cover the affected controls and authoritative native state; they do not claim
terrain rendering, every map, an entire match or physical-phone acceptance.

The complete v0.33 fallback APK/source ZIP/checksum remain unchanged under
`archive/fallback-0.34.json`; no v0.33 Git commit is assumed. Packaging verifies
fallback hashes, source scope, native lineage, APK assets/CRC, signing identity
and all proof/evidence hashes. It includes the full native source and soundtrack
once, excludes local caches/private files/delivery archives, checks every ZIP
entry against its source hash, and requires the complete source ZIP below the
2 GiB release-file limit. Raw native build caches and emulator data stay outside
the source archive; build recipes and hash-bound provenance remain inside it.

Outputs are `Warzone-Towers-0.34-Test-Ads.apk`,
`warzone-towers-0.34-source.zip` and
`Warzone-Towers-0.34-Test-Ads-SHA256.txt`. Packaging never overwrites an existing
delivery. GitHub publishing, older benchmarks, the privacy website and VPS
changes are outside this task.
