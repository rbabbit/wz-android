# Warzone Towers 0.38 — overlay ownership

This revision targets the reported Intelligence/build overlay leak. Its source
scope is the Intelligence frontend and build-display renderer, plus the exact
Android version bump. The existing native renderer, Java host, game rules,
orders, models, music, maps, wallet/saves, advertising and square unit controls
remain protected against the frozen v0.37 source and APK. No native relink or
copied asset pack is part of this version.

The regression fixture reproduced construction label `#1` showing through the
Intelligence preview with the preserved v0.37 renderer. Intelligence now exposes
a cheap `isOpen()` query covering opening, open and closing states. The existing
build-display visibility predicate uses that query to conceal its Canvas marks
throughout those states, including a failed close. Accepted sites, queued work,
line previews and demolition targets remain stored and redraw after Intelligence
closes, even when the camera has not moved. The six regression groups exercise
the actual modules and also retain no-Intelligence/Duel rendering equivalence.
The existing renderer fixture additionally passed its 161 ordinary preview and
accepted-label/module-geometry cases; syntax and Android build checks passed.

A static native review found the projection/GL restoration paths intact and no
model-shader path that replaces the terrain observer. Thin cyan strokes are
consistent with stock URBAN rain. That is an inference from the unchanged native
code, not runtime identification of the exact supplied pixels; weather was not
changed. There was no native edit or rebuild.

The user explicitly requested no emulator testing. Verification is limited to
source review, meaningful VM/Canvas API regression fixtures, Android compilation
and APK/source integrity. Those fixtures exercise the actual changed modules
through controlled APIs; they are not real Android GPU rendering, screenshots
or gameplay observations. The release record must keep `emulatorUsed:false`
and `gameplayVerified:false`. It does not establish that every visual leak or
prior startup/profile-change limitation is resolved on a phone.

`tools/check-overlay-leak-038.py` compares all protected original source files
without rerunning historical native/gameplay suites. Packaging accepts only
the exact built APK and a separately hash-bound, passed v0.38 regression report
that identifies its source-only scope and final input hashes. Every other app
asset, including the matched native JS/WASM/data and original soundtrack, must
retain its v0.37 bytes; identity, signing and sample-ad configuration are checked.

The complete v0.37 APK, source ZIP and checksums are preserved through
`archive/fallback-0.38.json`. The new complete source includes original code,
assets, native reproduction history and the scoped regression tool/proof, with
private/local caches, binary device backups and duplicate packs excluded. Every
ZIP entry is verified against its source SHA/CRC, and the file must remain below
the 2 GiB release-file limit. Older deliveries remain untouched.

Outputs are `Warzone-Towers-0.38-Test-Ads.apk`,
`warzone-towers-0.38-source.zip` and
`Warzone-Towers-0.38-Test-Ads-SHA256.txt`. No emulator, GitHub, VPS or privacy-site
changes are part of this task.
