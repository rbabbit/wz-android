## Correction

The native virtual droid returned by `getDroidProduction` does not export its
constructor/repair/brain/ECM/sensor equipment fields. The existing footer used
that incomplete design for its component strip; a constructor therefore lost
its Engineering image and failed comparison with the queued complete design.
The comparison failure forced incomplete-queue wording even when work progress
was correctly observed.

The existing Towers-only read-only factory observer now supplies the actual
current subject template through the original complete-template conversion.
The scenario validates that template against the fresh current subject before
normalizing its equipment. No parts are inferred from a name or guessed from
the app's last selection.

The footer uses one real matching thumbnail through the main Production list's
artwork selection, including Engineering for a confirmed constructor. Generic
body/wheel silhouettes are removed. An unverified image is hidden rather than
substituted with a made-up unit illustration.

Both Production views remove App waiting and Total unknown wording. Managed
queues keep supported current/waiting/remaining counts. If native queue
completeness is unverified, unsupported summaries are omitted. Existing real
work progress, percentage, held/power/capacity handling, estimated time, ADD
quantity and accepted orders remain unchanged.
