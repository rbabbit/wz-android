# Warzone Towers 0.44 — HUD, Home, autosave and real rewarded ads

## Visible changes

- The first main actions are Research, Manufacturing and Build in actual DOM
  and keyboard order. Other menu IDs, toggles and actions are retained.
- Visible Towers Production labels become Manufacturing. The footer Research
  button becomes Analysis; the main Research page remains Research.
- Analysis/Manufacturing share padding, alignment and tab treatment, with room
  for the longer label. Keyboard focus remains visible.
- Research stays prominent. Music highlights only while its menu is open,
  independently of whether music is playing.
- Wave/Skip Wave and its incoming-unit badge move slightly left, using a right
  safe inset. The user explicitly clarified the requested direction. Header
  scrolling reserves the matching space.

## Power and saves

The actual number still comes from the native power balance. Source inspection
found the stock fixed-scale gauge saturated at a few thousand power, so 2500
and 2800 could both appear full. Towers now uses 5000-power display headroom,
with larger display ranges as required. This changes the gauge scale, not power,
income, costs, queued reservations or production.

The native automatic-save feature is disabled before its messages, scheduling
and writes. Towers boot configuration also sets `autosaveEnabled=false` after
persistent config is loaded. Manual QuickSave calls `saveGame` directly and is
unchanged; Saved Games, wallet and blueprint persistence are retained. Existing
save files are not deleted.

The bounded native build changes only `intdisplay.cpp` and `loadsave.cpp`; source
patches, originals, recipe and provenance are in `archive/native-hud-0.44/`.
Every prior native fix, including production cancellation, and all 4292 authored
virtual files are preserved. No data, map, music or original artwork changes.

## Home and results

Normal cold startup selects the catalogue's first Easy level, Greenhaven. A
valid explicit map intent remains supported. This default is not reapplied
when returning from defeat or a saved battle: the played map stays selected.

While a result receipt is visible, Home hides its decorative tank, then restores
it through the common dismissal path. The receipt reserves space for the actual
Home version-label height, scrolls on shorter screens and isolates underlying
Home focus/accessibility. The grey tank, logo, layout and rbabbit version prefix
remain otherwise unchanged.

## Rewarded ads

The physical-phone delivery uses publisher app ID
`ca-app-pub-3430279660625393~3119801475` and rewarded unit
`ca-app-pub-3430279660625393/5338770704`, with `ADMOB_TEST_ADS=false`.
Optional opt-in viewing, UMP privacy/consent, ten-crystal native earned-callback
crediting and failure handling are unchanged. Emulator detection retains the
Google sample unit. For development or device ad testing, build explicitly with
`-PadmobLiveAds=false`. The delivery is built with `-PadmobLiveAds=true`.

No ad request is made during this revision's checks. The APK is configured for
real ads; actual serving, account/app eligibility and fill are not verified here.
No AdMob account, privacy website or VPS settings are changed.

## Fallback and verification

Complete delivered v0.43 APK/source/checksums are frozen by
`archive/fallback-0.44.json`. Older artifacts, v6.4 and GitHub benchmarks remain.

Verification is limited to focused source/VM checks, native and Android
compilation, and exact APK/source integrity. No emulator, browser, physical-phone
or native gameplay run is performed. Source inspection does not establish live
resource movement, actual manual-save operation, screen fidelity or ad serving.
The exact delivery and source inventory are recorded in
`archive/release-0.44-source-build-only.json`.
