# v0.56 — Native Home mode selection

The exact installed APK passed ten focused Home/navigation cases on emulator5558,
with no recorded runtime exceptions. Its SHA-256 is
`5e5c8cd15a95680e18a98a5474c0f70c14b0343eedf17c3040ad7657e543ff0e`.
The delivered v0.55 APK and complete source ZIP remain the immutable fallback,
recorded in `archive/fallback-0.56.json`.

Home now gives Campaign and Towers separate mode cards using the existing
black-and-white rounded controls. The official logo, grey tank and actual map
preview are reused. The giant “Choose your mode” heading and extra “Warzone
Towers” subtitle are omitted; Saved Games, Rewards and the Home-only
`rbabbit v0.56` label remain compact.

Campaign exposes NEW CAMPAIGN and CONTINUE directly. When its videos are ready,
New starts the original Alpha opening and Continue opens the separate Campaign
phone-save list. Missing videos use the existing download/setup screen without
launching a mission. Towers opens the existing difficulty/map browser: a cold
launch starts at Easy's first map, and map selection survives browser Back/reopen
and a match return. Home SAVED GAMES keeps its existing Towers store. No chapter
picker, online mode, reward rule or gameplay feature is added.

Product changes are limited to the native Home view, existing map-browser
presentation, MainActivity routes and version. Every web overlay, compiled
engine JS/WASM/data file, Campaign bridge/mission source, Towers/Duel scenario,
map, save format, soundtrack and other asset stays frozen to v0.55. There is no
native engine build, VFS append, download change or embedded payload rebuild.
The complete-source packaging gate retains every previous source entry, checks
the narrow Java inventory and matches the APK signing identity.

The ten native cases cover normal Home, Rewards and Towers-saves returns,
map selection/Back, an actual Towers launch and return, Campaign phone-save
Continue, a new Campaign opening, compact scrolling/map return, enlarged text
and restoration of the normal display. Captures cover 2400×1080 and 1280×720
physical layouts, with the compact profile also checked at font scale 1.3.
The three mode actions remain reachable with full 48dp touch targets.

Campaign Continue reused the existing phone checkpoint with its native Command
Centre. No units, power, research or structures were granted. The new Campaign
case fetched and displayed the original `c001.ogg` opening, skipped it with an
actual user tap, then observed ordinary Alpha with its three starting trucks.
This checks the route and opening readiness, not full movie playback or later
missions. The separate host proof `archive/home-0.56-route-checks.json` passed
fifteen compiled asynchronous route cases, including missing media and
stale/duplicate callbacks; those host cases are not emulator observations.

One fixture initially tried to tap a Previous Map control that is intentionally
hidden. It was corrected to swipe the observed native map-browser bounds and
wait for the selected index to change. The first three passed case records were
retained and the remaining journey resumed on the same unchanged APK. The
original fixture failure remains disclosed in the final report. Empty native UI
hierarchy reads were handled with bounded retries; neither fixture correction
changed product code or required a rebuild.

The approved reference and final visual comparisons are retained separately from
live screenshots in `archive/home-0.56`; `design-qa.md` records the visual review.
The final ten-case source report is `qa/home-056/verify-home-056.json`; the
recorder retains its per-case hash-linked observations for packaging.

This is a Home/navigation change, not a full Campaign/Towers playthrough.
Physical-phone performance, audible playback and live-ad serving are not claimed.
The emulator's existing terrain/shader limitation is separate from these layout
and native-readiness checks. Recording and packaging do not execute gameplay or
publish a release.
