# Warzone Towers 0.83 — Portrait Home

The mode-selection Home follows the selected second portrait design: a navy
slate background, the retained official logo and research tagline, a grey tank
and satellite-base hero, and four illustrated mode cards. Campaign, Towers,
FFA and Multiplayer retain their existing actions; Guide and Hub sit below
the cards. Captions, buttons, status and the `rbabbit` version label remain
native Android content rather than text embedded in the pictures.

`HomeModesView` uses the new pure `PortraitHomeLayout` helper. Normal portrait
widths use two card columns. Compact heights can scroll, and enlarged text can
fall back to one column. System insets, existing busy/error states and action
accessibility descriptions are retained. Artwork uses sampled bitmap decoding
for its displayed bounds.

Home requests portrait only while its unobscured mode-selection page is shown.
The existing Towers, Campaign, FFA, Multiplayer, Guide and Hub destinations
request landscape. `GraphicsSetupView`, `MainActivity`, the manifest and the
small `HomeOrientationPolicy` coordinate these transitions. MainActivity handles
orientation configuration changes by resizing its retained views instead of
recreating its game WebView. Exact-device navigation and restoration checks passed on the delivery APK,
including retained Activity and engine state.

## Artwork and preservation

Five new static PNG assets were individually generated with the built-in image
tool from the approved visual reference and inspected without image editing.
The hero is 1536×1024; the four mode images are 1691×930. They contain no baked
logo, captions, buttons or interface frames. Full prompts, dimensions, hashes
and copy provenance are retained in
`qa/portrait-home-083/art-provenance.json`; the exact selected reference is
retained beside it as `reference.png`. Existing official branding remains
unchanged.

The delivered v0.82 APK and complete source ZIP were verified before edits and
remain the fallback recorded in `qa/portrait-home-083/fallback.json`. Scope is
the native Home/orientation code, the five new images, version and release
documentation. Existing game assets, the v0.82 Multiplayer client/data, music,
maps, shared game interfaces and all unrelated Java/resources stay frozen.
The source package must retain every prior complete-source member.

## Validation status

Focused native geometry/text-metric and orientation-policy fixtures are kept
separate from Android observations. They cannot establish actual rendering,
touch behavior or Activity/game retention.

The exact installed delivery APK passed the Home and orientation journey on
emulator-5558 using ADB/CDP only, without desktop focus or visible PC-host input:

- All six actual Home controls opened their loaded landscape destinations and
  Android Back returned to portrait; the MainActivity token stayed unchanged.
- 390×844dp visual comparison, 360×740dp compact layout, 130% text with readable
  single-column scrolling, Guide/Hub reachability and a return to normal font size.
- Background/resume retained Home. A normal Greenhaven launch, Research open/close,
  physical Android finger swipe changing the native projection, background/resume
  retaining the same document/engine origins, and game→Towers map→portrait Home.
- Original 1080×2400/density300/font1.0 emulator overrides restored afterward.

The initial visual iterations fixed hidden-bar padding, hero seam/clipping,
reused background Paint alpha and runtime text-size refresh. Test-observer issues
were separate: historical Activity tokens, stale XML during rotation and a dialog
root incorrectly required to fill the screen. Actual screen observations corrected
those fixtures; no gameplay fix was made for them.

The existing emulator black-terrain limitation also appears in the older v0.79
Towers capture. The cause is unverified and remains outside this Home update.
The observed gameplay checks establish input/state retention, not terrain visual
quality, complete campaigns or public matches. No physical phone was tested.

The final log, installed APK hash, screenshots and state captures are pinned in
`qa/portrait-home-083/verification.json`. Host geometry/policy fixtures remain
separate from actual Android observations. The package tool validates current
pins, signing identity, artwork pixels, frozen existing APK members and complete
source preservation before writing delivery files.

The five added drawable names reassign build resource IDs. Existing compiled
launcher/splash and library XML may be relinked only when their complete decoded
trees and every changed reference word still resolve to the same resource names;
their source XML, existing image bytes, native libraries and game assets remain
frozen.

No GitHub or VPS changes are part of this revision.
