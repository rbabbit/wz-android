# v0.86 multiplayer background audit

The v0.85 failure was reproduced on the existing headless Android 16 emulator
in an isolated private room. Home put app UID 10235 into `LAST` with effective
network block `APP_BACKGROUND`, while Data Saver and power restriction were off.
At 00:45:54.711 Android destroyed that UID's live TCP sockets; the app immediately
logged `Software caused connection abort`. The public-directory DNS failure
followed at 00:45:55.100. The later cached-process freeze at 00:46:59 was not the
initial disconnect. This establishes separate transport and directory failures.

Raw evidence is retained in `qa/delivery-086/baseline085-netpolicy.txt`,
`baseline085-home-logcat.txt`, and `baseline085-home-failure.json`, with the
corresponding real screen captures. The unlisted host's reset/player-leave
observation is recorded by the root delivery run.

Android's network policy uses UID process state/capabilities to grant or block
background network access. Its connectivity service can close sockets for a
background firewall block as well as for a frozen UID. A foreground service is
therefore the direct protection for this app's Java socket UID. The active-session
service request now happens synchronously in the Join bridge, before engine
creation, covering an immediate Join → Home transition. It ends on explicit
leave/Activity destruction and does not recreate killed sessions.
Sources: [Android 16 network policy service](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android16-release/services/core/java/com/android/server/net/NetworkPolicyManagerService.java),
[network process capabilities](https://android.googlesource.com/platform/frameworks/base/+/HEAD/core/java/android/net/NetworkPolicyManager.java),
[connectivity socket destruction](https://android.googlesource.com/platform/packages/modules/Connectivity/+/refs/heads/main/service/src/com/android/server/ConnectivityService.java).

Chromium's hidden WebView scheduling and the stock engine's RAF pump are also
handled by an external adapter. That is supporting lifecycle protection, not a
claim that RAF caused the observed TCP abort. Input releases and music suspension
remain tied to the actual Android lifecycle.
Source: [Chromium WebView visibility](https://chromium.googlesource.com/chromium/src/+/main/android_webview/java/src/org/chromium/android_webview/AwContents.java).

The focused host proof executes the shipped RAF/directory code and actual Java
lifecycle/presentation methods with inert APIs. Android firewall exemption and
real room/match survival must be observed separately on the exact delivery APK.
No persistence after force-stop, process death, lost network or an ended native
match is promised.
