and concise directory retries, a manual VPS update action, and same-category

## Multiplayer

The baseline reproduction distinguished two failures. Android 16 put the app
UID under `APP_BACKGROUND` and closed its TCP socket after Home; the directory
DNS error occurred afterward. A later cached-process freeze was separate again.
See [the source and baseline audit](0.86-mp-background-audit.md).

A user-started live session now owns a nonsticky foreground service and a
background-only CPU wake lock. Its WebView/native frame pump remains active
without changing the compiled engine or protocol. Actual background input is
released and music suspends. Explicit Leave, destruction or task removal cleans
up the service. A killed process, force-stop, lost network or ended native match
cannot be recreated by this service.

Directory failure is short and shown once. The last successful room list stays
available and is explicitly marked stale. Manual Refresh, return and validated
network recovery use bounded retry; a live room/match is fenced from directory
refresh/reset. Actual room, Ready, chat/team/spectator and Leave paths are retained.

The exact candidate retained its real private waiting room and native match
through separate Home, Recents and screen-off/resume journeys. Native frame
and match clocks advanced; Android reported `FGS` and effective network block
`NONE`, compared with baseline `LAST`/`APP_BACKGROUND`. These were bounded
headless emulator checks with CDP attached, not a promise of indefinite physical
device survival. The private test host later exited after an idle match; this
was identified separately and a fresh prepared host was used for production.

One disclosed directory-fetch failure fixture showed one concise DNS message,
retained the 19 actual cached rooms and succeeded on a real network retry. It
did not replace any gameplay or TCP response. Native screenshots and fresh state
are in `qa/delivery-086/`.

## Manufacturing

ALL is present only when the lowest completed native factory ID of the selected
vehicle or cyborg category is selected. One explicit Manufacture action resolves
the owned, completed, compatible same-category factories in the actual engine.
Incompatible modules, unavailable designs, queue/capacity and normal production
constraints remain authoritative. Rendering does not enqueue work.

Cycle remains per factory. ALL plus cycle assigns the same repeat design across
eligible peers. Each factory has at most its normal bounded future repeat job.
Queue STOP remains local and cancels that factory's current/waiting work and
repeat. In ALL scope, cycle displays matching peer repeat state, so OFF remains
reachable after factory 1 was stopped; it preserves current finite work.

The shared implementation covers Towers, Campaign, FFA and Multiplayer. The
focused host checks execute the real queue/UI functions across all four modes,
including ownership, capacity, nonce deduplication, first-factory races, category
isolation, STOP and the stopped-first/group-cycle case. Twenty-eight headless
browser cases also exercise actual ALL/cycle/Manufacture controls and compact
layout. These host fixtures are supporting evidence, not native gameplay.

On the exact APK, the private native MP match produced new real constructor IDs
from both eligible vehicle factories and advanced to subsequent native subjects.
STOP-first, peer repeat, group OFF and category isolation passed. The available
single cyborg factory produced a new owned combat ID and repeated; multi-cyborg
coverage is recorded separately in the offline runtime evidence. A test recipe
filter initially mistook `ZNULLCONSTRUCT` for constructor equipment; that fixture
was corrected, and only its cyborg portion was rerun. No product change was
needed for that fixture failure.

The exact installed candidate also passed offline native production checks:
Towers with five vehicle and five cyborg factories, FFA with four vehicle
factories, and Campaign with three vehicle factories. Each had actual native
completion/repeat evidence, local STOP, group cycle OFF and clean cancellation.
Towers reached its ordinary 15-truck cap after nine new trucks; this is recorded
as a normal production constraint. An overly strict test assertion on a brief
idle handoff was corrected, and a separate fresh native follow-up verifies that
case without relabelling the original failed harness report.

Towers used the retained, explicitly seeded complete Iron Valley 5+5+5 checkpoint;
the extra facilities were not constructed during this run. FFA and Campaign used
normal prepared phone saves. The FFA save retains its older NullBot identity.
Early Campaign had no cyborg factory; native multi-cyborg coverage is Towers,
with single-factory cyborg completion also observed in MP. First/second factory
controls, compact/enlarged Towers and Home, and a real FFA finger pan after menu
return passed. All 32 original preference/save files were restored byte-for-byte,
along with the original display settings. Details and the initial fixture
failures are in `qa/delivery-086/offline475-runtime-summary.json`.

## Updates and delivery

Home's version footer opens Check for updates on request. There is no startup
popup. The strict HTTPS feed, full replacement download, byte count, SHA256,
package/version/minimum-SDK and same-signer checks precede Android installation
approval. Offline, progress, cancellation and retry use the manual dialog.
See [the update contract and limitations](../APP-UPDATES.md).

The public location is `https://wz2100.uk/downloads/warzone/`; the exact APK
filename is `warzone2100-andriod.apk`. Only the APK and feed are published there.
The VPS website, Caddy configuration and other hosted data are preserved.
Private source, signing files and secrets are excluded from public downloads.

This is a full APK update. No delta patching, remote code hot patching or silent
installation is implemented. Same application ID/signing identity and a normal
replacement install preserve existing app data; never uninstall to update.

The runtime update test used a clearly labelled private version-85 client built
from current code with the same app ID/signing key; it was not the preserved
historical v0.85 APK. It downloaded all 616662059 bytes from the live VPS once,
matched the exact candidate checksum and passed the real PackageManager checks.
Offline/retry, offer Back, unknown-source denial/return/allow, system installer
Cancel/retry and actual Android replacement approval were observed. The installed
APK hash matched the candidate, and all 24 original save ZIPs plus eight
preference files matched before and after launch. Manual Check then reported
the installed 0.86 as current. See `qa/delivery-086/update-runtime.json`.

The first native installation attempt failed from the test emulator's limited
storage. No app was uninstalled and no saves/private game data were deleted.
Android cache trimming and failed-staging cleanup freed space; a temporary
emulator low-storage reserve of 128 MiB was used for the successful retry and
restored to its original unset value. Free space had already increased before
that retry, so success is not attributed solely to the reserve adjustment.
Unknown-source/network/display settings were also restored. This is disclosed
fixture recovery, not a claim about every handset's available installation space.

After that real replacement install, another private MP match retained its native
clock through Home and accepted a real Android finger pan on return. Native
camera coordinates changed, then explicit Leave returned to Home and stopped
session protection. The post-game comparison retained every original save,
wallet, design and player-preference file; only WebView's `origins_visited_date`
bookkeeping changed after that additional visit. The original 32/32 immediate
upgrade comparisons remain separately recorded without hiding this later change.

The complete source ZIP retains every v0.85 source member, including full native
source, the frozen compiled engines, maps and soundtrack. Only the three scoped
command VFS entries are appended; the original data prefixes and unrelated
virtual files remain unchanged. Exact build, runtime, VPS and package evidence
and its limits are recorded in `qa/delivery-086/verification.json` and
`archive/release-0.86.json`.

The inherited emulator black-terrain limitation remains. No physical-phone,
full-campaign, all-map balance, force-stop recovery or live-ad testing is claimed.
