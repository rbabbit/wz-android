# Optional Play Games achievements — 0.99.14

Delivery target: a normal test APK. This revision prepares 18 achievement definitions and persistent native-result progress. It does not claim that achievements, leaderboards or cloud operations have succeeded against Google services.

The approved definitions cover three Campaign goals, three Towers goals, three Survival goals, two FFA goals, two Challenge goals, three downloaded-Maps goals and two Multiplayer goals. Their canonical titles, descriptions, points, standard/incremental types and targets are in `app/src/main/assets/warzone/play-games-definitions.json`. Definitions have stable application keys, not invented Google achievement IDs.

Actual achievement and leaderboard IDs still require the user's manual Play Console setup. Import the prepared achievement ZIP in Console, obtain the generated resource XML/IDs, and map those IDs to the stable application keys. Leaderboards additionally need explicitly matching mode, map, difficulty, bot, player count and team/strategy rules. The app-side definitions alone do not create Console resources or activate their buttons.

Play Games remains optional and OFF by default. Local gameplay, saves and Crystals continue without a connection. The existing explicit connection and manual cloud-backup features remain separate from the new achievement definitions. Unpublished Play Games resources require the appropriate PGS tester access.

Progress is retained in private account-scoped history. Native waves, completed missions and match results use stable run identities so duplicate events and save/load returns do not repeatedly award progress. Unconnected local history can be explicitly assigned to the selected account; it is not silently attributed to a later account. Incremental facts contain absolute progress rather than repeated increments. Capacity failures preserve previously committed history.

Spectators and unverified Multiplayer terminal events do not count. Reliable native local Multiplayer results may support its completion/victory achievements. Multiplayer leaderboard candidates require additional server verification; this revision does not treat a local terminal result as a server-verified online score. Wave boards use highest cleared wave with a time tie-break; fastest-victory boards use elapsed milliseconds, with separate context classifications.

Achievement progress history is currently separate from the manual cloud save/Crystals backup. Restoring that backup does not restore this local history. See the [native event contract](../play-games-progress-events.md) for required evidence, identities, bounds and submission-fact fields.

No tests, emulator sessions, browser automation, QA checks or service submissions were performed for this revision. Runtime behaviour and Google achievement/leaderboard integration remain unverified. No APK, VPS update, GitHub release or Google Play rollout is uploaded by this documentation change.
